Getting started with cvpa

cvpa gives you weighted party support and policy-issue attitudes by demographic group, over time, from Canadian public-opinion surveys going back to 1945. As of version 0.2.0, that covers several hundred policy questions across seven issue domains – economy and taxation, energy and environment, health/education/social programs, immigration/diversity/ federalism, foreign policy and identity, social issues/rights/justice, and democracy and institutions – in addition to vote choice and intention. From cvpa’s point of view, vote is just one more question: it’s decoded and analyzed the same way as any policy question.

Two ways to use cvpa

There are two separate paths through the package, and it’s worth being clear about which one you’re on:

  • The live data path (update_cvpa_data(), question_catalog(), question_data(), wtd_response(), response_gap_analysis()) reads Parquet files hosted alongside the policy-attitudes web app, covering every question in the catalog. This is almost certainly what you want for new analysis.
  • The legacy vote path (vote_data, wtd_vote(), gap_analysis()) is the original vote-choice/intention dataset and functions the package shipped with before 0.2.0, kept as-is for reproducing prior work (in particular Lucas, Romualdi, Armstrong, and Goodyear-Grant (2025) on the Canadian Vote Intention Dataset, Canadian Journal of Political Science 58 (3): 666-80). wtd_vote()/gap_analysis() are, under the hood, thin wrappers around the same general engine that powers the live data path, so their behavior hasn’t changed – see the last section of this vignette.

This vignette focuses on the live data path, since that’s what’s new.

library(cvpa)

Setting up the local cache

cvpa doesn’t bundle policy-attitude data in the package itself – there’s too much of it, and it’s updated periodically as new survey waves are added. Instead, update_cvpa_data() downloads what you ask for into a local cache (see cvpa_cache_dir()) the first time you need it, and every other function reads only from that cache. Nothing in the package other than update_cvpa_data() ever touches the network, so you’re always in control of when a download happens.

The question catalog and the demographic/party code-labels table are small and are always refreshed by update_cvpa_data(). Respondent-level data for a specific question is only fetched when you name it (there are several hundred questions, so there’s deliberately no “fetch everything” option – the full dataset is available as dataset.parquet from the cvpa_dataset repository):

update_cvpa_data(questions = "bri_econ_013")
#> Fetching question catalog (vbl_data.parquet)...
#> Fetching code labels (code_labels.parquet)...
#> Fetching 1 question file(s)...
#>   [1/1] bri_econ_013

Weighted response shares over time

A quick look at how the “More” category (support for reducing the rich-poor gap) has moved over time, by gender:

library(ggplot2)
more_by_year <- subset(wtd_response(d, grouping_vars = "gender"), response == "More")
ggplot(more_by_year, aes(x = year, y = response_share, color = gender)) +
  geom_line() +
  geom_point() +
  scale_color_manual(values = c(Man = "steelblue", Woman = "firebrick")) +
  labs(
    x = "Year", y = "Share answering \"More\"",
    title = "Support for reducing the rich-poor gap, by gender",
    color = NULL
  ) +
  theme_minimal()

Vote is just another question

Because vote choice and intention live in the same catalog and the same resp/question=<code>/data_0.parquet layout as every policy question, everything above works identically for "vote_choice"/"vote_intention":

update_cvpa_data(questions = "vote_choice")
#> Fetching question catalog (vbl_data.parquet)...
#> Fetching code labels (code_labels.parquet)...
#> Fetching 1 question file(s)...

vc <- question_data("vote_choice", years = 2000:2021)
